# DeepAware OpenArm v2 simulation

Deterministic MuJoCo joint-space tracking for the OpenArm v2 **left seven-DoF
arm only**. The primary path is headless Python with named model mapping,
torque-mode PD plus MuJoCo bias-force compensation, pre-step safety checks, CSV
logging, metrics, and plots.

The selected official model is `v2/openarm_bimanual.xml` from
`openarm-mujoco==2.0.1`. Source evidence, parameter classifications, motor
limits, conflicts, and the hardware identification plan are in
[`docs/PARAMETER_PROVENANCE.md`](docs/PARAMETER_PROVENANCE.md).

## Setup and demo

From a clean checkout with Python 3.11:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.experiment --mode baseline --headless --output results/baseline
```

Viewed execution uses the same experiment model and controller:

```powershell
.\.venv\Scripts\python.exe -m src.experiment --mode baseline --viewer --output results/baseline_viewer
```

Run deterministic regression tests and lint with:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests
```

## What the implementation proves

- Exactly `openarm_left_joint1` through `openarm_left_joint7` and
  `left_joint1_ctrl` through `left_joint7_ctrl` are selected by name.
- Joint IDs, qpos addresses, DoF addresses, and actuator IDs are resolved and
  validated once at startup; controller and safety code use the stored mapping.
- The vendor v2 actuators are position servos. The loaded model is adapted only
  in memory to fixed gain-one, zero-bias torque actuators after verifying joint
  transmission, target, gear, command magnitude, and sign. Vendor files remain
  unchanged.
- Every step is preceded by finite-value, desired planning-limit, measured hard
  position, measured velocity, hard requested-torque, tracking-divergence, and
  normal torque-clamping checks. A safety fault stops stepping and exits
  nonzero.

## Limitations

MuJoCo `qfrc_bias` compensates gravity, Coriolis, and centrifugal terms, but not
joint damping or `frictionloss`. The small steady-state residual in the plots is
therefore expected and was documented rather than suppressed with aggressive
gains. Integral action or explicit friction feedforward would be the appropriate
later remedy. Model inertials/passive terms are estimates, J7 has a documented
DM3507/DM4310 source conflict, and this simulation is not authorization for
hardware motion.

See [`docs/AI_WORKFLOW.md`](docs/AI_WORKFLOW.md) for the evidence-first agent
workflow and [`AGENTS.md`](AGENTS.md) for the governing engineering rules.
